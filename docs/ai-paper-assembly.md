# AI 智能组卷：技术选型

需求：老师上传学生情况（学段、年级、成绩、薄弱点等），选定要考查的知识点，设置难度、总分等，AI 从校本题库中选题并赋分；以对话形式交互，可多轮修改。

## 一、总体方案：检索和凑分交给算法，AI 负责理解需求、挑题和解释

让大模型直接从题库选题并赋分，实际中容易出现以下问题：

- **总分对不上**：模型算不准，常出现 148 分或 152 分。
- **编造题目 ID**：可能给出题库中不存在的题。
- **题库放不进上下文**：上万道题塞不进去，成本也高。
- **难以复现和解释**：同样的输入可能组出不同的卷子，出了问题不好排查。

因此分三层，每层只做自己擅长的事。输入为学生情况、知识点、难度设置与对话内容，依次经过：

| 步骤 | 执行者 | 做什么 |
|---|---|---|
| ① 规划 | 大模型 | 把需求整理成「组卷蓝图」：知识点 × 题型 × 难度区间 × 题量 × 分值；输出固定格式的数据，后端逐项校验 |
| ② 求解 | 程序 | 按蓝图检索候选题 → 选题（知识点覆盖、平均难度、去重、排除学生做过的题）→ 按模板赋分；总分与各项约束由程序保证，题不够时明确报告缺口 |
| ③ 复核与对话 | 大模型 | 只能从候选清单中挑题、换题（ID 必须在清单中），说明组卷思路，处理「第 12 题太难换一道」「导数加到 20 分」这类修改 |

AI 仍可「自由挑选」，但范围限定在程序给出的候选清单内；分值与约束由程序兜底，保证正确。

## 二、各环节选型

| 环节 | 推荐 | 不推荐 / 以后再考虑 | 理由 |
|---|---|---|---|
| 大模型接入 | 在 [llm.py](../server/app/pipeline/llm.py) 中新增支持多轮对话与工具调用的流式函数 | LangChain / LangGraph、LlamaIndex | 工具调用循环约 200 行即可；沿用现有用量统计、失败重试与测试模拟方式，也符合项目「直接调 HTTP 接口、便于换厂商」的原则 |
| 模型 | 通义千问 qwen-plus / qwen-max 或 deepseek-chat（非思考模式），均支持工具调用 | 思考模式与工具调用同时开启 | 各厂商对「思考 + 工具调用」的支持不一致，需实测。规划一步可用较强模型，复核用较便宜的模型 |
| 候选题检索 | 复用 [bank.py](../server/app/bank.py) 的知识点子树、题型、难度筛选，以及 [similar.py](../server/app/similar.py) 的相似度去重 | 现在就引入专门的向量数据库 | 万题以内全量扫描够用；题量更大时换 PostgreSQL + pgvector |
| 选题算法 | 贪心选题 + 逐步调整，纯 Python 实现，不加依赖 | 一开始就用 OR-Tools CP-SAT | 候选题通常不超过 200 道，贪心足够。约束变多（考试时长、同一材料题绑定等）时再换 CP-SAT（镜像约增加 30 MB），接口先预留 |
| 赋分 | 按学段、学科、考试类型建立赋分模板（如新高考数学：单选 8×5、多选 3×6……），解答题按难度微调；AI 提出的调整须通过校验 | 完全由 AI 定分 | 分值要符合考试惯例，且必须凑整 |
| 学生情况 | 结构化表单为主，辅以自由文本；可选上传成绩单、错题（PDF / Excel 复用现有解析流程）；薄弱点用 [knowledge.py](../server/app/pipeline/knowledge.py) 对应到知识树的具体知识点 | 只存一段自由文本 | 对应到知识点后算法才能使用；以后接入作答数据时结构不必改 |
| 个性化难度 | 简单规则：目标难度 = 学生在该知识点的水平 + 偏移量（薄弱点出基础题，强项出提高题） | IRT 能力模型、知识追踪 | 这些方法依赖作答数据，目前没有 |
| 流式推送 | 后端 FastAPI `StreamingResponse` 推 SSE；前端 `fetch` + `ReadableStream` 自行解析 | WebSocket；浏览器自带 `EventSource`（仅支持 GET） | 单向推送够用，部署简单 |
| 对话界面 | Vue 自行实现对话面板，公式渲染复用 `MathText`，markdown 用 markdown-it | 前端 AI 对话框架（多为 React 优先，且要求配套后端协议） | 界面需求具体，自己实现更可控 |

## 三、交互形式：对话 + 参数面板并排

纯对话不适合调整精确参数（如「难度 0.45、总分 150」）。页面左侧为对话，右侧同时显示：

- **组卷蓝图表**：知识点 × 题型 × 难度，可直接修改；修改后同步给 AI。
- **试卷预览**：每道题提供「换一道 / 换更难的 / 删除」。
- 确认后调用试题篮现有的 `fromBank`，把题目连同分值写入试题篮，后续沿用已有的排版与导出 Word 流程。

对话过程中后端推送以下几类消息，界面实时显示进度：

- AI 回复文字（逐字显示）；
- 工具执行进度，如「正在检索：函数单调性 · 中档 · 找到 34 道」；
- 试卷草稿更新（结构化数据）；
- 缺口提示，如「三角函数的难题题库中只有 1 道」。

AI 可调用的工具：

| 工具 | 作用 |
|---|---|
| 更新蓝图 | 修改知识点、题型、难度区间、题量、分值 |
| 检索候选题 | 按知识点、题型、难度检索，返回精简清单 |
| 求解组卷 | 按蓝图选题并赋分，返回试卷草稿与缺口 |
| 换题 | 按条件替换指定题目，新题须在候选清单中 |
| 调整分值 | 修改题目或大题分值，校验总分 |
| 加入试题篮 | 把确认后的试卷写入试题篮 |

每个工具的参数用 pydantic 定义并校验，校验失败时把错误返回给模型重试。

## 四、数据模型

新增以下数据表：

| 表 | 内容 |
|---|---|
| StudentProfile（学生档案） | 别名、年级、教材版本、目标、薄弱知识点及掌握度、备注、上传文件 |
| AssemblySession（组卷会话） | 关联的学生档案、组卷蓝图、当前试卷草稿（只存题目 ID 与分值）、状态 |
| AssemblyMessage（对话消息） | 对话与工具调用记录，便于排查与回放 |
| 学生用题记录 | 每个学生用过的题，下次组卷时自动排除 |

注意：

- 发给模型的是试卷草稿摘要（题号、知识点、难度、题干前 60 字），而非完整题目，避免上下文越来越长。
- 固定的系统提示词放在请求最前面，以命中厂商缓存、降低费用。

## 五、风险

1. **未成年人个人信息**：按《个人信息保护法》，不满十四周岁未成年人的个人信息属于敏感个人信息。发给大模型前去掉姓名等身份信息，只传别名；只收集组卷需要的字段；数据按学校隔离并支持删除；上传时由用户确认已获授权。
2. **题库覆盖不足**：组卷质量的最大瓶颈。求解失败时明确告知缺口，并给出替代方案（放宽难度、换相邻知识点）。「AI 现场出新题」以后再做，且须单独标注。
3. **题目配图**：AI 看不到图片。选题只依赖知识点、难度等标注，影响不大，但复核时不能让 AI 评价图片内容。
4. **效果评价**：复用现有评测页面，指标包括约束满足率、实际难度与目标的偏差、知识点覆盖率、试卷内重复题比例，以及老师导出前替换的题目数（最能反映实际效果）。

## 六、分阶段实施

| 阶段 | 内容 |
|---|---|
| P1 | 不含对话：学生档案表单 + 选知识点 + 设难度 → 程序生成蓝图、选题、赋分 → 写入试题篮。先把选题与赋分的核心算法做扎实，不依赖大模型 |
| P2 | 加入对话层：AI 规划蓝图、多轮修改、流式显示、对话与面板并排 |
| P3 | 从成绩单或作答数据估计学生各知识点掌握度，再考虑能力模型与 CP-SAT 求解 |

### 7.2 Demo 范围

| 模块 | 做法 |
|---|---|
| 页面 | 新增一个「AI 组卷」页面：对话输入框 + 难度滑块 + 总分输入 + 试卷预览 |
